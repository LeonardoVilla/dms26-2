🎯 Objetivo da aula

Hoje completamos as quatro operações do CRUD (Create, Read, Update, Delete) adicionando edição e exclusão de alunos, e vamos exibir mensagens de erro de validação de forma amigável no formulário.

📚 Conceitos

Route Model Binding

O Laravel consegue injetar automaticamente o registro do banco correspondente ao ID da URL, direto como parâmetro do método do Controller. Por exemplo, ao acessar /alunos/3/editar, o Laravel já entrega o objeto Aluno com id = 3 pronto, sem você precisar buscar manualmente com Aluno::find($id).

Validação e mensagens de erro

Quando $request->validate() encontra um erro, o Laravel automaticamente redireciona de volta ao formulário anterior, guardando os erros numa variável especial chamada $errors, disponível em toda view.

🛠️ Passo a passo

1Adicione as novas rotas

Em routes/web.php, dentro do mesmo grupo auth:

Route::get('/alunos/{aluno}/editar', [AlunoController::class, 'edit'])->name('alunos.edit');
Route::put('/alunos/{aluno}', [AlunoController::class, 'update'])->name('alunos.update');
Route::delete('/alunos/{aluno}', [AlunoController::class, 'destroy'])->name('alunos.destroy');
2Implemente os métodos no Controller

Adicione ao AlunoController (repare que o Laravel já entrega o $aluno certo, graças ao Route Model Binding):

public function edit(Aluno $aluno)
{
    return view('alunos.edit', compact('aluno'));
}

public function update(Request $request, Aluno $aluno)
{
    $dados = $request->validate([
        'nome' => 'required|string|max:255',
        'email' => 'required|email|unique:alunos,email,' . $aluno->id,
        'cpf' => 'required|digits:11|unique:alunos,cpf,' . $aluno->id,
        'data_nascimento' => 'required|date',
        'telefone' => 'required|string|max:20',
        'curso' => 'required|string|max:255',
    ]);

    $aluno->update($dados);

    return redirect()->route('alunos.index')->with('status', 'Aluno atualizado com sucesso!');
}

public function destroy(Aluno $aluno)
{
    $aluno->delete();

    return redirect()->route('alunos.index')->with('status', 'Aluno removido com sucesso!');
}
Por que unique:alunos,email,$aluno->id? Ao editar, o próprio aluno já possui aquele e-mail cadastrado. Esse terceiro parâmetro diz ao Laravel "ignore o registro com esse ID" ao checar duplicidade — senão o formulário nunca conseguiria salvar sem mudar o e-mail.
3Crie a view de edição

Crie resources/views/alunos/edit.blade.php — praticamente igual ao formulário de criação, mas usando o método PUT e preenchendo os valores atuais:

<x-app-layout>
    <div class="max-w-xl mx-auto py-6">
        <h1 class="text-xl font-bold mb-4">Editar aluno</h1>

        <form method="POST" action="{{ route('alunos.update', $aluno) }}">
            @csrf
            @method('PUT')

            <label>Nome</label>
            <input type="text" name="nome" value="{{ old('nome', $aluno->nome) }}" class="border w-full mb-1">
            @error('nome') <p class="text-red-600 text-sm">{{ $message }}</p> @enderror

            <label>E-mail</label>
            <input type="email" name="email" value="{{ old('email', $aluno->email) }}" class="border w-full mb-1">
            @error('email') <p class="text-red-600 text-sm">{{ $message }}</p> @enderror

            <label>CPF</label>
            <input type="text" name="cpf" value="{{ old('cpf', $aluno->cpf) }}" class="border w-full mb-1">
            @error('cpf') <p class="text-red-600 text-sm">{{ $message }}</p> @enderror

            <label>Data de nascimento</label>
            <input type="date" name="data_nascimento" value="{{ old('data_nascimento', $aluno->data_nascimento) }}" class="border w-full mb-1">

            <label>Telefone</label>
            <input type="text" name="telefone" value="{{ old('telefone', $aluno->telefone) }}" class="border w-full mb-1">

            <label>Curso</label>
            <input type="text" name="curso" value="{{ old('curso', $aluno->curso) }}" class="border w-full mb-4">

            <button type="submit" class="bg-red-600 text-white px-4 py-2 rounded">Atualizar</button>
        </form>
    </div>
</x-app-layout>

A diretiva @method('PUT') é necessária porque formulários HTML só suportam GET e POST nativamente — o Laravel "finge" o verbo PUT através de um campo oculto.

4Adicione os links de editar/excluir e as mensagens de erro na listagem

Atualize alunos/index.blade.php, adicionando uma coluna de ações e o bloco de erros de validação (útil também na tela de criação):

@if ($errors->any())
    <div class="mb-4 text-red-600">
        <ul>
            @foreach ($errors->all() as $erro)
                <li>{{ $erro }}</li>
            @endforeach
        </ul>
    </div>
@endif

...

<th class="border p-2">Ações</th>

...

<td class="border p-2">
    <a href="{{ route('alunos.edit', $aluno) }}" class="text-blue-600 underline">Editar</a>

    <form method="POST" action="{{ route('alunos.destroy', $aluno) }}" class="inline" onsubmit="return confirm('Excluir este aluno?')">
        @csrf
        @method('DELETE')
        <button type="submit" class="text-red-600 underline">Excluir</button>
    </form>
</td>
5Teste o fluxo completo

Cadastre um aluno, edite os dados dele, tente salvar um formulário com campo vazio (veja o erro aparecer) e, por fim, exclua um aluno de teste.

Cuidado ao excluir: a exclusão que fizemos hoje é definitiva (chamada de "hard delete"). Em sistemas reais, muitas vezes se usa "soft delete" (marca como excluído sem apagar de fato) — mas isso fica fora do escopo do nosso curso introdutório.
