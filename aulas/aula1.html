Aula 1 — Criando um projeto Laravel sem instalador global

Disciplina: Desenvolvimento Web com Laravel · Carga horária: 2h

Sem privilégios de administrador Banco: SQLite Aula 1 de 6

🎯 Objetivo da aula

Hoje vamos criar o esqueleto do nosso projeto final: um sistema de cadastro de alunos (CRUD) construído com Laravel, Jetstream, Livewire e SQLite. Ao final desta aula, você terá o projeto rodando localmente no navegador — sem precisar instalar nada como administrador do laboratório.

🧩 O que precisa estar instalado na máquina

Diferente do que a documentação oficial recomenda como primeira opção (o instalador global laravel new), vamos usar o Composer diretamente, criando o projeto dentro de uma pasta comum, sem exigir permissão de administrador. Para isso funcionar, a máquina do laboratório precisa ter:

RecursoPara que serveComo verificar
PHP (8.2 ou superior) Linguagem em que o Laravel é escrito e executado php -v
Composer Gerenciador de dependências do PHP — baixa o Laravel e suas bibliotecas composer -V
Extensão PDO SQLite do PHP Permite ao Laravel conversar com um banco SQLite (arquivo único, sem servidor) php -m (procure por pdo_sqlite)
Node.js e npm Compilar o CSS/JS do front-end (Jetstream usa isso nas próximas aulas) node -v e npm -v
Se algum comando não for reconhecido: avise o professor antes de tentar instalar qualquer coisa. Em laboratório com restrição de administrador, geralmente PHP/Composer/Node já vêm pré-instalados pela equipe de TI — o bloqueio costuma ser apenas para instalações globais feitas por você, que é justamente o que vamos evitar hoje.

🚫 Por que não vamos usar laravel new

O comando laravel new depende de um pacote instalado globalmente (composer global require laravel/installer). Em muitos laboratórios, escrever fora da pasta do projeto — mesmo que seja só na pasta do seu usuário — pode ser bloqueado por política do administrador. Para não depender disso, vamos usar o Composer no modo create-project, que baixa o Laravel inteiro dentro da própria pasta do projeto, sem tocar em nada fora dela.

🛠️ Passo a passo

1Escolha onde vai criar seus projetos

Crie (ou use) uma pasta de trabalho, por exemplo Documentos\laravel-projetos. Abra o terminal (PowerShell ou Prompt de Comando) dentro dela.

2Crie o projeto com o Composer

Rode o comando abaixo. Ele vai baixar o Laravel e todas as dependências direto para dentro de uma nova pasta chamada cadastro-alunos:

composer create-project laravel/laravel cadastro-alunos

Esse comando pode levar alguns minutos na primeira vez, pois baixa vários pacotes PHP.

3Entre na pasta do projeto 
cd cadastro-alunos
4Configure o banco de dados SQLite

O Laravel já vem preparado para SQLite. Precisamos apenas criar o arquivo de banco vazio:

# Windows (PowerShell)
New-Item -ItemType File -Path database\database.sqlite -Force

# Se estiver usando o Prompt de Comando (cmd), use:
type nul > database\database.sqlite
5Confirme o arquivo .env

Abra o arquivo .env (na raiz do projeto) e verifique se a variável de conexão está assim:

DB_CONNECTION=sqlite

Pode deixar (ou apagar) as demais linhas DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME, DB_PASSWORD — o SQLite não precisa delas, pois usa um arquivo local em vez de um servidor de banco.

6Rode as migrations padrão

Isso cria as tabelas básicas do Laravel (usuários, sessões, etc.) dentro do seu arquivo SQLite:

php artisan migrate
7Suba o servidor local 
php artisan serve

Abra o navegador em http://127.0.0.1:8000. Se aparecer a tela de boas-vindas do Laravel, deu certo! 🎉

Dica: deixe esse terminal com php artisan serve aberto durante toda a aula. Para rodar novos comandos (como os das próximas aulas), abra um segundo terminal na mesma pasta do projeto.

📌 O que é cada coisa que acabamos de usar

  • Composer: gerenciador de pacotes do PHP — parecido com o npm do JavaScript. Ele lê o arquivo composer.json do projeto e baixa tudo que é necessário.
  • Artisan: a ferramenta de linha de comando do próprio Laravel (php artisan ...). Vamos usá-la o curso inteiro para gerar código e rodar tarefas.
  • Migration: um "script de versionamento" do banco de dados. Cada migration descreve uma alteração nas tabelas (criar, alterar, remover). Vamos criar a nossa própria migration de alunos na Aula 3.
  • SQLite: um banco de dados que vive dentro de um único arquivo (database.sqlite), sem precisar instalar nem configurar um servidor de banco separado. Ideal para aprendizado e para ambientes com restrição de instalação.
